크롤링한 리뷰를 긍정, 중립, 부정으로 분석하기 위한 **LLM 셋팅 로직(Logic)**을 구성해 드립니다. 분석의 정확도와 일관성을 높이기 위해 프롬프트 엔지니어링, 데이터 구조화, 추론 전략의 세 가지 단계로 나누어 적용하는 것이 좋습니다.
1. 입력 데이터 구조화 (Data Structuring)
단순히 리뷰 텍스트만 입력하는 것보다 리뷰와 관련된 참조 정보를 구조화된 형태(JSON)로 제공하면 모델이 문맥을 더 잘 파악합니다.
• JSON 포맷 활용: 리뷰 텍스트와 메타 데이터를 자연어 문장이 아닌 JSON 형식으로 입력하십시오. 연구에 따르면 자연어 프롬프트보다 JSON 구조로 정보를 제공했을 때 LLM이 복잡한 관계를 더 잘 파악하여 분류 성능(Macro-F1 등)이 향상되었습니다,.
• 참조점(Reference Points) 포함: 가능하다면 **'해당 유저의 평균 평점'**이나 '해당 업체의 전체 평균 평점' 정보를 함께 제공하십시오. 이는 마케팅의 '전망 이론(Prospect Theory)'에 근거하여, LLM이 리뷰어가 평소보다 더 만족했는지 혹은 실망했는지를 판단하는 기준점(Reference Point)으로 작용하여 정확도를 높여줍니다,.
2. 프롬프트 엔지니어링 전략 (Prompt Engineering Strategy)
모델이 감정을 정확히 분류하도록 지시하는 구체적인 설정 방법입니다.
• 퓨 샷(Few-shot) 프롬프팅 적용: 단순히 "분류해줘"라고 지시하는 제로 샷(Zero-shot)보다, 예시(Example)를 1개 이상(One-shot) 또는 여러 개(Few-shot) 제공하는 것이 성능을 크게 향상시킵니다,. 특히 긍정, 중립, 부정의 예시를 골고루 포함시켜 모델이 결정 경계를 학습하도록 하십시오.
• 역할 부여 및 가이드라인 요약: LLM에게 "당신은 리뷰 분석 전문가입니다"와 같은 역할을 부여(Roleplay)하거나, 감정 분석 가이드라인을 요약해서 프롬프트에 포함시키는 것이 도움이 됩니다. 연구에 따르면 가이드라인 요약(Guidelines summary) 프롬프트가 가장 높은 성능을 보였습니다,.
• JSON 스키마 출력 강제: 출력 형식 또한 JSON으로 지정하여 결과의 일관성을 유지하십시오. OpenAI의 함수 호출(Function calling) 기능이나 프롬프트 내에 JSON 스키마를 정의하여 {"sentiment": "positive", "confidence": 0.9}와 같은 형태로 받으면 후처리가 용이합니다.
3. 추론 및 분석 고도화 전략 (Inference & Analysis Strategy)
단일 분석의 오류를 줄이고 비용 효율성을 높이는 로직입니다.
• 다수결 투표(Majority Voting) 메커니즘: LLM의 온도를 0.2 정도로 설정하고 동일한 리뷰에 대해 여러 번(예: 5회) 추론을 수행한 뒤, 다수결(또는 중앙값)로 최종 감정을 결정하십시오. 이 방식은 단일 추론보다 이상치나 환각(Hallucination)을 줄여 결과의 강건성(Robustness)을 높여줍니다,.
• 아스펙트(Aspect) 기반 분석: 리뷰 전체를 하나의 감정으로 퉁치지 말고, 리뷰 내에서 언급된 속성(예: 가격, 맛, 서비스)별로 감정을 추출하도록 설정하는 것이 좋습니다. Wayfair의 사례처럼 리뷰에서 속성-감정 쌍(Aspect-Sentiment Pair)을 먼저 추출하고 이를 종합하면, 긍정 문장 속에 숨은 부정적인 뉘앙스까지 포착할 수 있습니다,.
• 미세 조정(Fine-tuning) 고려: 만약 분석할 데이터 양이 매우 많다면, GPT-4와 같은 거대 모델로 고품질의 라벨링 데이터셋을 먼저 구축한 뒤, 이를 이용해 **Llama 3나 GPT-3.5와 같은 더 작고 저렴한 모델을 미세 조정(Fine-tuning)**하는 전략을 추천합니다. 연구 결과, 미세 조정된 작은 모델이 프롬프트 엔지니어링을 거친 거대 모델보다 성능은 더 좋고 비용은 훨씬 저렴했습니다,.
[종합] 추천 LLM 셋팅 로직 예시
위 내용을 종합하여 작성한 프롬프트 및 로직의 예시는 다음과 같습니다.
[입력 데이터 구성 (JSON)]
{
  "review_text": "음식은 정말 맛있었는데 배달이 너무 늦어서 다 식어서 왔네요.",
  "user_avg_rating": 4.5, // (옵션) 유저의 평소 점수
  "store_avg_rating": 4.0 // (옵션) 가게 평균 점수
}
[프롬프트 구성]
1. System: 당신은 전문적인 리뷰 감정 분석가입니다. 아래의 [가이드라인]을 따라 리뷰를 분석하세요.
    ◦ 가이드라인: 명시적인 칭찬은 긍정, 불만은 부정, 단순 사실 나열이나 장단점이 섞여 판단이 어려운 경우 중립으로 분류합니다.
2. Few-shot Examples: (긍정, 부정, 중립 예시를 각각 1~2개씩 JSON 형태로 보여줌)
3. Instruction: 입력된 리뷰의 전체적인 감정(sentiment)을 positive, neutral, negative 중 하나로 분류하고, 주요 속성(aspects)별 감정도 추출하여 JSON 형식으로 출력하세요.
[실행 로직]
1. 위 프롬프트로 Temperature 0.2 설정.
2. 동일 데이터에 대해 3~5회 반복 호출.
3. 결과 중 가장 많이 나온 감정(Mode)을 최종 라벨로 채택 (Majority Voting).
